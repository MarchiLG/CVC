COMPUTER VISION CENTRAL — HOW TO USE
======================================

QUICK START
-----------
    ./run.sh

First run creates a .venv, installs everything in requirements.txt
(this is a big download — torch + ultralytics + insightface together
are 1GB+, expect several minutes), and copies .env.example to .env if
you don't have one yet. Every run after that just launches the app.

To force a dependency reinstall later (e.g. after editing
requirements.txt):
    ./run.sh --reinstall


BEFORE YOUR FIRST REAL RUN
---------------------------
1. Edit .env with your actual camera credentials:
       CAM1_URL=rtsp://user:password@192.168.1.3:554/...
       CAM2_URL=rtsp://user:password@192.168.1.4:554/...


2. Edit config/cameras.yaml to match how many cameras you have and
   what each one is called. Each entry's "url" should reference an
   env var, e.g. url: "${CAM1_URL}".


WHERE THINGS ARE CONFIGURED
----------------------------
config/cameras.yaml   which cameras exist, their name/URL/enabled flag
config/tasks.yaml     what each camera is watching for (see below)
config/app.yaml       global defaults: device, database, LLM narrator,
                       desktop notifications
.env                  camera credentials (never committed)

Both cameras.yaml and tasks.yaml can also be edited live from the GUI
(Configurações / Calibração tabs) — those edits preserve comments and
formatting, so hand-written notes in the YAML files survive GUI saves.


WHERE TO CHANGE MODEL SETTINGS
--------------------------------
There are three independent models in this app, each configured in a
different place:

1) YOLO object detection (used by item_counting, ppe_compliance,
   missing_product):
   - Per-camera-task override: set "model:" on that task in
     config/tasks.yaml, e.g.:
         - type: item_counting
           model: yolov8s.pt
   - Global default (used when a task doesn't set "model:"):
     config/app.yaml -> vision.model_size_override
         vision:
           model_size_override: yolov8m.pt
   - If neither is set, the app auto-picks yolov8s.pt on CUDA or
     yolov8n.pt on CPU (see next point).

2) Device (CPU vs GPU) for both YOLO and face recognition:
   config/app.yaml -> vision.device: auto | cpu | cuda
       vision:
         device: cuda
   "auto" detects CUDA at startup. If you force "cuda" on a machine
   without a GPU, the app logs a warning and falls back to CPU
   automatically — it will NOT crash.

3) Face recognition model (used by face_id):
   - Per-task override: config/tasks.yaml, inside that face_id task's
     params:
         - type: face_id
           params:
             model_pack: buffalo_l     # or buffalo_s
             device: cuda              # optional, overrides vision.device just for this task
   - If not set, it follows the same device resolution as YOLO:
     buffalo_l on CUDA, the lighter buffalo_s on CPU.

4) LLM narrator model (the local Ollama model that writes plain-
   language summaries of recent alerts):
   config/app.yaml -> llm.model
       llm:
         enabled: true
         model: qwen2.5:1.5b
   This has to be a model you've already pulled with Ollama — see
   "Enabling the LLM narrator" below.


PER-CAMERA TASKS (config/tasks.yaml)
--------------------------------------
Each camera can have one or more tasks. Built-in task types:
    item_counting     — counts things crossing a line (params:
                         counting_line, direction, target_classes,
                         min_count_per_window, window_seconds)
    missing_product    — flags an empty zone that should have an
                         object in it (params: zones, with a name,
                         polygon and expected_class each;
                         absence_dwell_seconds)
    ppe_compliance     — flags a person missing required safety gear
                         (params: required_ppe, zones,
                         missing_ppe_dwell_seconds). Needs a model
                         actually trained on PPE classes — the
                         default YOLO model (COCO) does NOT know what
                         a helmet or vest is, so point "model:" at a
                         PPE-trained checkpoint before enabling this.
    face_id            — flags unrecognized faces (params:
                         match_threshold, log_unknown, device,
                         model_pack). See "Enrolling employees" below
                         — with nobody enrolled, every face is
                         "unknown".

Easiest way to set up counting lines and zones: use the Calibração tab
in the GUI instead of hand-typing pixel coordinates — capture a live
frame, click the points, save.

Every task has a "flags" list controlling what actually gets raised:
    flags:
      - id: missing_ppe
        enabled: true
        severity: warning        # info | warning | critical
        notify: [log, desktop]   # any of: log, desktop, db
"notify: [db]" only does something if db.enabled: true in app.yaml.


ENABLING OPTIONAL FEATURES
-----------------------------
Desktop notifications (on by default):
    config/app.yaml -> notify.desktop.enabled: true/false

Event log in SQLite (off by default — persists every flag to
data/app.db's event_log table, in addition to the console log):
    config/app.yaml -> db.enabled: true

Employee database (always on, no toggle — SQLite file at
data/app.db, created automatically on first run):
    Enroll people from the "Funcionários" tab in the GUI: capture from
    a camera or upload a photo, type a name, click Cadastrar.

LLM narrator (off by default, requires Ollama installed separately —
it's not a pip package):
    1. Install Ollama: https://ollama.com/download
    2. Start it:            ollama serve
    3. Pull a small model:  ollama pull qwen2.5:1.5b
       (or llama3.2:1b — anything small enough to run acceptably on
       CPU; this is just a text summarizer, not the vision model)
    4. config/app.yaml -> llm.enabled: true, llm.model matching what
       you pulled.
    If Ollama isn't running, the narrator logs a warning every cycle
    and the "Resumo (IA)" panel just stays empty — nothing else in
    the app is affected.


USING THE GUI
----------------
Ao vivo         Live grid of every configured camera, with detection
                boxes drawn over whichever task is assigned to each.
Calibração      Freeze a live frame from a camera and click to draw a
                counting line or a zone polygon for one of its tasks.
                Saves straight into tasks.yaml.
Configurações   Per-camera task list: add/remove tasks, edit
                detect_fps, edit required_ppe, toggle/edit flags.
Funcionários    Enroll employees for face_id (capture or upload a
                photo + name). Lists everyone already enrolled.
Alertas (dock)  Live table of recent flags, plus the LLM narrator's
                latest summary at the top (if enabled).


RUNNING THE TEST SUITE
-------------------------
    source .venv/bin/activate
    pytest tests/ -v

All tests run without needing real cameras or a running Ollama
instance. One test (test_vision_integration.py) downloads yolov8n.pt
and one (test_face_recognizer_integration.py) downloads the buffalo_s
face model on first run if not already cached.


WHERE FILES LAND
-------------------
data/app.db             SQLite: employees, face embeddings, event log,
                         narration log. Gitignored.
~/.insightface/models/  Downloaded face recognition model packs
                         (buffalo_s/buffalo_l), cached across runs.
*.pt in project root     Downloaded YOLO weights (e.g. yolov8n.pt),
                         cached across runs. Gitignored.


TROUBLESHOOTING
-------------------
"vision.device='cuda' solicitado mas CUDA não está disponível"
    Expected and harmless if this machine has no NVIDIA GPU — it just
    means device: cuda in app.yaml fell back to CPU automatically.
    Set device: auto or device: cpu to stop seeing this.

"Falha ao chamar Ollama" warnings every ~60s
    Expected if llm.enabled: true but Ollama isn't installed/running.
    Either start Ollama (see above) or set llm.enabled: false.

Torch/onnxruntime install is CPU-only by default
    requirements.txt installs the CPU wheels. For an NVIDIA GPU
    machine, install the CUDA build of torch first (see the comment
    in requirements.txt, or https://pytorch.org/get-started/locally/)
    and swap onnxruntime for onnxruntime-gpu — the two are mutually
    exclusive, install only one.

A camera never connects / GUI shows "aguardando conexão..."
    Check the RTSP URL and credentials in .env, and that the camera
    is reachable on the network (e.g. `nc -zv <ip> 554`).
